# telegram-notify

Плагин для Claude Code: шлёт в Telegram сообщение, когда Claude закончил ход, упал с ошибкой API, просит доступ или задаёт вопрос.

## Что ловит

| Событие | Когда | Сообщение |
|---|---|---|
| `Stop` | ход закончен | ✅ + текст последнего ответа |
| `StopFailure` | ход убит ошибкой API | 🚧 / 💳 / ⛔ … + тип ошибки |
| `Notification` | нужен доступ, ждёт ввода, фоновый агент закончил | 🔐 / 💤 / 🤖 … |
| `PreToolUse: AskUserQuestion` | Claude задаёт вопрос | ❓ + вопрос и варианты |

`StopFailure` — главное, ради чего это писалось: `Stop` при падении хода **не срабатывает**, и без этого события кажется, что Claude ещё работает. Ловятся все 13 типов ошибок, включая `rate_limit`, `overloaded`, `billing_error`, `account_on_hold` и `max_output_tokens`.

Из `Notification` пропускаются 9 типов из 15. `auth_success`, `elicitation_*`, `computer_use_*` и `push_notification` отсеиваются матчером — процесс для них даже не запускается.

## Планы приходят вместе с уведомлением

Если в финальном сообщении есть ссылка на файл плана, он отправляется следом за ✅ — ссылка на локальный файл с телефона бесполезна, а сам план нужен.

- короче 3000 символов — текстом прямо в чат;
- длиннее — файлом, с первыми 900 символами в подписи, чтобы один план оставался одним уведомлением, а не четырьмя.

**Читаются только файлы внутри `planDirs`** (по умолчанию `~/.claude/plans`). Это граница безопасности, а не удобство: в сообщении может оказаться ссылка на любой путь в системе, и без ограничения хук стал бы каналом утечки. Всё остальное — файлы вне каталога, обход через `..`, не-`.md`, несуществующие пути, внешние URL — молча игнорируется.

## Установка

**Требуется Node.js 18+** (нужен глобальный `fetch`). Сам Claude Code работает на Node, так что обычно он уже есть.

### 1. Поставить плагин

Из локальной папки:

```bash
claude --plugin-dir /путь/к/claude-telegram-notify
```

Через marketplace (переживает перезапуск, ставится один раз):

```
/plugin marketplace add /путь/к/claude-telegram-notify
/plugin install telegram-notify@telegram-notify
```

Из git — так удобнее всего раскатывать на несколько машин:

```
/plugin marketplace add https://github.com/ВАШ_ЮЗЕР/claude-telegram-notify
/plugin install telegram-notify@telegram-notify
```

### 2. Подключить бота

На **каждой** машине отдельно — токен в плагин не входит и в репозиторий не попадает.

1. В Telegram: **@BotFather** → `/newbot` → скопировать токен
2. Написать новому боту любое сообщение (иначе он не имеет права отвечать первым)
3. Запустить:

```bash
node "/путь/к/claude-telegram-notify/scripts/telegram-setup.mjs" ВАШ_ТОКЕН
```

Скрипт сам найдёт `chat_id` через `getUpdates`, сохранит `~/.claude/telegram-notify.json` и пришлёт тестовое сообщение.

> **Токен попадёт в историю оболочки** — он передаётся аргументом командной строки. Либо почистите историю после настройки, либо сразу задайте `chat_id` вручную и впишите токен в конфиг руками.

### 3. Перечитать конфиг

`/reload-plugins`, либо перезапустить Claude Code.

## Настройка

`~/.claude/telegram-notify.json` — только эта машина, в репозиторий не коммитится:

```json
{
  "botToken": "…",
  "chatId": "…",
  "minTurnSeconds": 30,
  "events": { "stop": true, "failure": true, "notification": true, "question": true },
  "sendPlans": true,
  "planDirs": ["C:/Users/вы/.claude/plans"],
  "planInlineMaxChars": 3000,
  "planMaxFiles": 3,
  "planMaxBytes": 1000000
}
```

- `minTurnSeconds` — не слать ✅ для ходов короче N секунд. `0` = слать всегда. Рекомендую 30–60, иначе телефон звенит на каждую мелочь.
- `events` — выключить отдельный тип уведомлений. `failure` лучше не трогать, это самое полезное.
- `sendPlans` — приложить план к ✅. `false` отключает целиком.
- `planDirs` — каталоги, файлы из которых разрешено отправлять. Расширяйте осознанно: всё, что сюда попадёт, сможет уехать в Telegram по ссылке из сообщения. По умолчанию `~/.claude/plans`.
- `planInlineMaxChars` — граница «текстом или файлом».
- `planMaxFiles` — максимум планов на одно уведомление, чтобы сообщение со списком ссылок не превратилось в лавину.
- `planMaxBytes` — потолок размера файла.

Все ключи, кроме токена, необязательны — старый конфиг без них продолжает работать на значениях по умолчанию.

Вместо файла можно задать переменные окружения `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` — они имеют приоритет. Так токен вообще не ложится на диск.

## Если что-то не приходит

Ошибки пишутся в `~/.claude/telegram-notify.log`. Хук всегда выходит с кодом 0 и никогда не роняет сессию, поэтому молчание лога — признак, что всё в порядке.

Частые причины:

- Боту не написали первым — Telegram вернёт `403: bot can't initiate conversation`.
- Конфиг не найден — в логе будет `missing botToken/chatId`.
- Плагин поставлен, но конфиг не перечитан — `/reload-plugins`.

## Про дубли

Если на машине уже висят эти же хуки в `~/.claude/settings.json`, уберите оттуда блок `hooks` — иначе каждое событие уйдёт в Telegram дважды.
